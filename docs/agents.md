# cancho-flow

> A run is a claim you can check. `flow step` runs one program as a recorded step; `flow-records` reads the records back.
> Generated by scripts/site.py from the built programs; the same facts as https://alpibrusl.github.io/cancho-flow/.

## What it does

- `flow step` starts one program from a directory baked into the binary, with exact arguments, no shell, an environment that holds only `PATH`, a deadline and an output cap.
- It hashes the program's own file and every file named by `--in` before, and every file named by `--out` after, and writes a canonical record `DIR/<id>.<oid>.json`:
  `id` is the SHA-256 of what determined the outcome, `oid` of the outcome, and a `check` covers every byte. No clock time, host, absolute path or payload is recorded.
- `flow-records list|show|check` reads them; `check` says which of the program, the inputs and the outputs no longer match.
- Not built: `replay`, `compare`, memoisation, `--keep-output`, plans (docs/design.md section 11). It is not a scheduler, a shell or a sandbox.

## Commands

```
flow step [--root DIR] --record DIR [--in P,P] [--out P,P] [--stdin | --stdin-file P] [--stdout-file P] [--max-stdin N] [--deterministic] [--allow-failure] [--answer-output] [--timeout-ms N] [--max-output N] [--format json|text] -- PROGRAM [ARG...]
flow-records list|show|check [--root DIR] [--format json|text] DIR [ID[.OID]]
```

Answers are one JSON line, schema `flow.v1`: `{ok, command, schema, data, error, errors, meta}`. Match on `error.rule`, never on `message`.

## Refusal rules

- `args.bad-value` (exit 2): a flag's value is not of the flag's kind
- `args.duplicate-flag` (exit 2): the same flag was given twice
- `args.missing-operand` (exit 2): an operand the tool needs was not given
- `args.missing-value` (exit 2): a flag that takes a value was given none
- `args.unexpected-value` (exit 2): a flag that takes no value was given one
- `args.unknown-flag` (exit 2): a flag that is not in the tool's table
- `flow.args.not-utf8` (exit 2): an argument, a declared path or the program name is not UTF-8, and a record holds only text
- `flow.args.too-many` (exit 2): more arguments than a record may hold
- `flow.check.inputs-changed` (exit 5): a declared input is not what the record names (changed, or gone)
- `flow.check.outputs-changed` (exit 5): a declared output is not what the record names (changed, or gone)
- `flow.check.program-changed` (exit 5): the program's file is not the one the record names
- `flow.files.too-many` (exit 2): more declared files than a record may hold
- `flow.program-name` (exit 2): the program is not one plain name (it is empty, `.`, `..` or has a `/`)
- `flow.program-not-found` (exit 3): the programs directory holds no program of that name
- `flow.record.ambiguous` (exit 5): the id has more than one record (one per outcome)
- `flow.record.damaged` (exit 8): a file already under this record's name is not this record
- `flow.record.too-large` (exit 8): a record file is larger than a record may be
- `flow.record.too-many` (exit 8): the record directory already holds the most records
- `flow.record.unknown` (exit 3): the directory holds no record with that id
- `flow.spawn-failed` (exit 8): the operating system could not start the program or its channels
- `flow.stdin.conflict` (exit 2): --stdin and --stdin-file are both given, and a step has one standard input
- `flow.stdout.undeclared` (exit 2): --stdout-file names a file that --out does not list, and the file the standard output is written to is an output of the step
- `flow.step.failed` (exit 8): the program ended with a non-zero status or a signal (the record was written)
- `flow.step.not-deterministic` (exit 5): a step declared deterministic gave another outcome than an earlier record of the same inputs (nothing was written)
- `flow.step.output-missing` (exit 8): the program ended with status 0 but did not leave a file declared with --out (the record was written)
- `flow.verb` (exit 2): the first operand is not a verb this program has (it has `step`)
- `io.is-a-directory` (exit 2): a directory where a file is wanted
- `io.not-a-directory` (exit 3): a path runs through something that is not a directory
- `io.not-found` (exit 3): a named input does not exist
- `io.permission-denied` (exit 4): the operating system refused access
- `limit.input-too-large` (exit 8): an input longer than --max-bytes
- `limit.output-too-large` (exit 8): the program wrote more than --max-output to one stream and was killed
- `limit.timeout` (exit 8): the program ran past --timeout-ms and was killed
- `path.absolute` (exit 2): an absolute path where one relative to --root is wanted
- `path.dotdot` (exit 2): a path with a `..` component
- `path.empty` (exit 2): an empty path
- `path.outside-root` (exit 4): an absolute path that is not under --root
- `path.symlink` (exit 4): a path that runs through a symbolic link, which the tool does not follow
- `path.too-long` (exit 2): a path longer than 4096 bytes

## Honest limits

- It records what the caller declares and cannot see a file a program reads or writes without being told; a cached step (when memoisation exists) can then be wrong.
- A secret in an argument is recorded: keep secrets in files named with `--in`, where only a hash is recorded.
- Tested on Linux x86-64 only; "the same bytes on every platform" is open until a fingerprint is checked on more than one.
- One counted user so far (cancho-consulting).
